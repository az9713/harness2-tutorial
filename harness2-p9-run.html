Project 9 run, step by step

One live run of project9/ through the released harness2 code (commit 1cfe254). Each step names the harness2 function that ran, the paper stage, and the harness files it touched.

The run. Task ledger-1 only (--tasks 1), budget k = 1, sequential mode, in WSL, on 2026-10-25. Claude Code with Haiku did the task runs. Sonnet did the editor, composer and reflector sessions. The 4 task runs report "apiKeySource": "none", which is the Claude subscription login. The 4 sessions ran in the same shell, where the guard found no billing variable. Nothing was billed.

What the record does not show


    

  • Tool calls inside the sessions. The editor, composer and reflector sessions run with --output-format json. The record keeps each session's mission (*.mission.md), reply (*.response.md), duration and cost, but not the tool calls inside it. The 4 task runs use stream-json, so their tool calls are complete.
    • 

  • Exact start times. The record has end times (file write times) and durations, not start times. The run start, ≈ 08:15:34, is the end time minus the 2 min 37 s total, which includes the uv start-up.
    • 

  • Level 2 in this run. With one task, the library is written but no editor reads it. Step 17 shows the read from the earlier 3-task run in project9/runs/live/.
    • 

  • The Windows shims. This run was in WSL, so the two Windows shims in adapter.py (fcntl stand-in at line 22, read_tree replacement at line 36) did not run. On native Windows, the read_tree replacement runs in steps 3 and 7, and the fcntl stand-in runs in step 15.
    • 

  • A tie, not a gain. The base run and the final both scored 1. In base1, Haiku did not obey the harness and calculated the total itself. In an earlier live run of the same task, base1 wrote Total: 105.25 and scored 0. One run per arm cannot show that the edits made the harness better; the reflector also rated its own confidence "low".
